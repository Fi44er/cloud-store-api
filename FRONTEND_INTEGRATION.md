# 🚀 Frontend Integration Guide: Cloud Store API

Этот документ содержит полные инструкции для фронтенд-разработчика по интеграции с бэкендом Cloud Store. Здесь описано, как работать с файловой структурой, как интерпретировать объекты и как правильно отрисовывать иерархию.

---

## 1. Общие принципы

### Авторизация
Все запросы к `/api/v1/files/*` требуют авторизации. Бэкенд ожидает сессию Kratos.
- Если используется браузер: сессия передается через Cookie (`ory_kratos_session`).
- Если заголовок: `X-Session-Token` или стандартный `Authorization: Bearer <token>`.

### Базовый URL
Все эндпоинты начинаются с: `/api/v1`

## 2. Работа с файловой иерархией

Бэкенд хранит файлы и папки как **Ноды (Nodes)**. Структура в базе данных — плоская, но логически древовидная за счет поля `parent_id`.

### Структура объекта Node
```json
{
  "id": "uuid",           // Уникальный ID ноды
  "name": "filename.png", // Отображаемое имя
  "is_dir": false,        // true для папок, false для файлов
  "parent_id": null,      // ID родительской папки. null = Корень (Root)
  "size": 102456,         // Размер в байтах (0 для папок)
  "mime_type": "image/png",
  "extension": ".png",
  "is_favorite": false,   // Метка "Избранное"
  "created_at": "2024-..."
}
```

### Как отрисовывать иерархию (Алгоритм)
Бэкенд возвращает плоский список. Чтобы правильно отобразить содержимое конкретной папки:

1.  **Корневая директория (Root)**:
    Отфильтруйте список так, чтобы остались только объекты с `parent_id == null`.
2.  **Вход в папку**:
    При клике на папку сохраните её `id` как `currentFolderId`. Перерисуйте интерфейс, отфильтровав список по `parent_id == currentFolderId`.
3.  **Навигация (Хлебные крошки)**:
    Для построения пути "Назад" фронтенду нужно либо хранить историю навигации (стек ID), либо рекурсивно искать родителей в общем списке.

#### Пример кейса (из вашего запроса):
У вас 8 нод. В корне 1 папка и 3 файла. Остальные 4 ноды лежат внутри этой папки.
- **Отображение корня**: Проходим по всем 8 нодам -> Рисуем только те 4, у которых `parent_id: null`.
- **Отображение папки**: При заходе в папку -> Рисуем оставшиеся 4 ноды, у которых `parent_id` равен ID этой папки.

## 3. Эндпоинты

### `GET /files` — Получение списка
Поддерживает фильтрацию и пагинацию.
- **Query параметры**:
    - `page`, `limit` — для пагинации.
    - `search` — поиск по имени.
    - `extension` — фильтр по расширению (например, `.jpg`).
    - `min_size`, `max_size` — фильтр по размеру (в байтах).

**Важно**: Бэкенд возвращает объект `{ "files": [...], "total": 100 }`.

### `POST /files/folder` — Создание папки
**Body (JSON)**:
```json
{
  "name": "Новая папка",
  "parent_id": "uuid" // (опционально) если создаем внутри другой папки
}
```

### `POST /files/upload` — Загрузка файла
Используйте `Multipart Form Data`.
- `file`: сам файл.
- `parent_id`: (опционально) ID целевой папки.

### `GET /files/download/:id` — Скачивание
Прямая ссылка для скачивания файла. Бэкенд установит правильные заголовки `Content-Type` и `Content-Disposition`.

## 4. Дополнительные функции

### Квота (Storage Usage)
`GET /files/quota`
Возвращает данные в **байтах**:
- `total`: общий объем (5 ГБ).
- `used`: занято.
- `free`: свободно.
- `pct`: процент заполнения.

### Активность и Heatmap
`GET /files/activity`
Возвращает два типа данных:
1. `logs`: Список последних действий (кто, когда, какое действие).
2. `heatmap`: Агрегированные данные для графика активности (сколько загрузок было в каждый из последних 365 дней).

### Избранное
`POST /files/favorite/:id`
**Body (JSON)**: `{ "is_favorite": true/false }`

## 5. Советы по UX/UI
- **Форматирование размера**: Используйте библиотеку (или функцию), чтобы превращать байты в человекочитаемый вид (КБ, МБ, ГБ).
- **Иконки**: Определяйте иконку на основе `is_dir` (если папка) или `extension` (если файл).
- **Drag-n-Drop**: При загрузке через DnD в конкретную область, не забывайте передавать `parent_id` текущей открытой папки.
- **Кеширование**: Рекомендуется использовать `React Query` или `SWR` для управления списком файлов и квотой.
